Resulting behavior

  • Webhook-only collection writes unsupported rows to a private SQLite queue before acknowledging them. Status shows pending rows.
  • Replay deletes queued rows only after database commit. Stale snapshots cannot replace fuller turn evidence.
  • Cursor and Pi keep one aggregate per turn. Published timestamps and human prompt identities stay stable across resumed reads.
  • The scheduler serializes runs, retries incomplete daily work, and closes only its own SSH child.
  • Evaluation scores follow changed inputs. Missing clones stay undecided; negative PR answers remain eligible for a later lookup.

Limits and rollout

Update the installed package before copying the new scheduled wrapper; the wrapper calls aut scan-job.

Apply the optional UPDATE(attrs) grant as the database administrator to enable covered corrections. Until then, normal delivery continues and corrections remain queued. Run aut retry-delivery afterward.

This snapshot records verification before publication. It does not report deployment status. Database checks used a disposable PostgreSQL instance; live grant and collector checks belong to the release verification.

Deleted source blobs cannot be reconstructed. Indivisible API page saturation stops safely for operator recovery. SIGKILL cannot execute cleanup. Source-coverage hashes grow with a turn.

Crash recovery still uses at-least-once delivery and stable sink identities. That is a required safety property, rather than a defect to remove.
